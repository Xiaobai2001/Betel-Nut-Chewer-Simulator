# 微信小程序原生源码 · 1.5.1

## 直接导入

1. 微信开发者工具首页 → **导入**，选择本文件所在目录（必须能看到 `project.config.json`，不要只选 `miniprogram`）。
2. 项目名可填「嚼槟榔模拟器」。AppID 已填 `wxa4973df8756ffee9`；选择 **小程序**。如果询问后端服务，选择 **不使用云服务**，本项目使用现有自建 MySQL 后台。
3. 点击导入、编译。无需安装 npm 依赖，也无需「构建 npm」。建议使用开发者工具稳定版，基础库 3.7.12 或更高。
4. 默认直接使用访客功能：咀嚼/吐渣/换包、吸吐烟、旋转和拖动、沉浸布局、音效、统计、成就、现实打卡及省钱设置。
5. 发布前点击「预览」用手机微信测试；这里只交付源码，不会替你提交审核或发布。

**AppID 提醒：**当前开发者工具基本信息把所提供 AppID 显示为「接口测试号」。它可以用于开发体验，正式发布需到微信公众平台注册正式小程序，并把这里的 `project.config.json` 中 `appid` 换成其正式 AppID。AppSecret 不写入源码。

## 功能与边界

- WXML / WXSS / JavaScript 原生页面。1.5.1 通过微信 Three.js 适配层直接复用网页 `src/immersive-scene.js` 的三维几何、纹理、咀嚼形变、烟雾和吐渣逻辑；不再使用 1.5.0 的简化多边形模型。手机页面保留网页的标题、健康提示与包装外观。
- 微信的 Three.js 适配层与网页引擎版本不同，光照细节可能有少量差异，不承诺逐像素一致。WebGL 不可用时使用网页 `app/visuals.js` 的槟榔绘制函数作为兼容画面，界面会明确标注。
- 修复微信 style-v2 默认按钮宽度导致的访客标签竖排、控件撑宽和横向裁切；主操作与包装采用可收缩列宽。
- 包装容量与现有网页一致：50 / 100 / 200 档分别 10 / 15 / 20 颗；香烟每盒 20 根。记录按实际开始使用的数量折合包装，换包动作本身不计消耗。
- 现实打卡与虚拟用量分开，成就鼓励停下、呼吸练习和真实自报戒除，不奖励大量消耗。
- 省钱基准由每人填写，未设置不显示金额；修改基准会重算历史估算。
- 访客数据仅存当前小程序本机存储，不上传、不合并到账号。清理存储会丢失访客记录。
- 云端使用原网页用户名/密码，**未接入微信一键登录或 OpenID**。账号 ID 来自现有数据库，不重新建账号编号。
- 登录用户的模拟操作断网时排队，按账号和接口地址隔离；重试去重。打卡和消费设置需联网，失败会提示，未成功不算保存。
- 与原网页一致，云端日用量按服务器收到操作时的北京时间归档；跨天离线补传归入补传当天，累计数保持准确。
- 会话过期后重新登录原账号继续补传；有未同步记录时禁止切换到另一账号，避免遗漏或串号。
- 本次不重建 EXE / APK，也不包含客户端 OTA。

## 连接现有云账号

现在 `miniprogram/config.js` 的 `apiBase` 为空，登录按钮不可用。这是可体验的本机版本，不是假登录。

1. 先按配套 `ChewSimulator-1.5.0-WebAccounts.zip` 的 README，将现有账号后台升级至 1.5.0。使用 `Update-Accounts.ps1`，保留原 `.private`、数据库和账号。1.5 不新增数据库表。已有 1.5.0 后台可继续使用，本次视觉修正不要求重建数据库。
2. 准备完成备案的域名和有效 HTTPS 证书，将域名通过反向代理指向现有 Node 服务（原服务一般为 8081）。证书必须可信、链完整、域名匹配。只开放网页静态目录不能提供账号 API。
3. 反向代理须保留 `Authorization` 请求头。确认 `https://你的域名/api/health` 返回版本 1.5.0。不要把数据库端口公开给小程序。
4. 微信公众平台 → 开发管理 → 开发设置 → **服务器域名**，把此 HTTPS 域名加入 `request` 合法域名。
5. 把 `miniprogram/config.js` 的 `apiBase` 改为 `https://你的域名`，不带末尾 `/api` 或路径。填入运营者的公开联系渠道 `contact`。随后重新编译、预览并上传。
6. 用原网页账号登录；核对账号 ID、原统计、打卡和省钱设置。访客记录不会覆盖原账号。

你此前提供的公网 IP `101.201.68.203` + HTTP 不能作为微信正式版的网络接口。网页可维持现状；小程序云同步需上述 HTTPS 域名。若调整网页的访问域名，先同步旧网址下的待上传记录；网站 `publicOrigin` 与实际访问地址一致。小程序 Bearer 接口不要求把网站 Cookie 来源改成微信地址。

### 本机开发

只有开发环境可显式把 `allowInsecureDevelopment` 设为 `true`，并使用 `http://127.0.0.1:端口` 或 `http://localhost:端口` 调试本机后台。开发者工具的域名校验仍由操作者自行设置；这不是上线方案。体验版/正式版拒绝此 HTTP 配置。手机的 127.0.0.1 指向手机自己。

### 原生 API

`/api/native/register`、`login` 返回 `{user,token}`，其余接口通过 `Authorization: Bearer <token>` 认证；令牌有效期 14 天，服务端只保存令牌摘要。`session` / `stats` 是 GET，`logout` / `events-v2` / `checkin` / `savings` 是 POST。事件格式与网页协议 2 相同。原网站仍使用 HttpOnly Cookie 和原来源校验，不把 Cookie 当原生凭证。

## 正式发布前

核对正式 AppID、主体和小程序备案、真实服务类目、用户隐私保护指引与运营联系方式。按实际包含的虚拟互动和健康记录如实申报；若平台判定属于小游戏，应按小游戏要求办理，当前 `compileType: miniprogram` 工程不能直接宣称满足小游戏准入。源码可导入不等于平台审核已通过。具体资质以公众平台当前要求为准。

隐私说明位于「我的 → 使用说明、健康提示与隐私说明」。本项目无广告 SDK、不索取微信手机号或麦克风权限。若你后续增加收集项，应同步更新代码与平台隐私申报。运营者需处理反馈渠道收到的数据查询/更正/删除申请。

手机验收：咀嚼至 100% → 吐出 → 取新颗；燃尽后再点一根；拖动、缩放、旋转；音效开关；沉浸底部操作；切后台停止自动咀嚼/呼吸；访客重启记录保留；两账号分别登录；断网后重连补传；原网页与微信记录一致。
