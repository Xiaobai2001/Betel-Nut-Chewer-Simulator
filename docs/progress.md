# 记录、包装与戒除成就（网页 1.4.0）

入口：左侧或手机底部的 **记录与成就**，也可从账号统计窗口进入。所有云端记录按当前登录账号隔离；访客不保存到账号。

## 模拟用量

| 指标 | 计入时机 |
| --- | --- |
| 咀嚼次数 | 有效嚼一口，自动咀嚼也计数 |
| 嚼过颗数 | 每颗第一口；未嚼就吐出不算 |
| 嚼完颗数 | 每颗首次到达 100%（15 口） |
| 点燃根数 | 每次成功点燃新香烟，点燃后马上熄灭也计一根 |
| 吸过根数 | 每根第一次吸入；仅自然燃尽不算吸过 |
| 抽完根数 | 吸入或自然燃烧首次到达 100%，只计一次 |
| 吸烟口数 | 成功吸入一次，必须先吐出才能再吸 |
| 提前吐出 | 已嚼但未到 100% 时吐出或开始放下练习 |
| 提前熄灭 | 尚在燃烧且未耗尽时主动熄灭或开始放下练习 |
| 休息分钟 | 完整完成一次页面的一分钟呼吸练习，累计 1 分钟 |

点燃、吸过、抽完三个数字含义不同。烟盒用量按“点燃根数”折算，因为这根香烟已被取用。模拟动作不是现实摄入，不作为真实戒断疗效或医学依据。

## 包装容量与展示

- 50 档：每袋 **10 颗**。
- 100 档：每袋 **15 颗**。
- 200 档：每袋 **20 颗**。
- 香烟：每盒 **20 根**；用空当前盒后再点燃，会自动取新盒。
- 初始 50 档包已取一颗放在模拟口中，因此初始显示剩余 **9 / 10**。当前口中的槟榔在换档后保留，仍归属它原来的档位。
- 刷新页面或换账号会重置当前模拟与手中包装；**账号累计消耗不重置**。

包装区展示的是 **折合消耗**，不是点击换包次数。例如嚼过 50 档 11 颗、100 档 15 颗，会显示“1 袋 + 1 颗”和“1 袋的量”，合计折合 2.1 袋。点燃 25 根显示“1 盒 + 5 根”，合计 1.25 盒。反复换包、换盒、刷新页面不会凭空增加计数。

包装图形会显示空袋形变、烟盒开盖、叠放及总数，并显示零散用量。数量很大时以叠放和倍数表达，避免一次渲染几千个包装。可切换今日/累计，今日按北京时间归属。

旧版 1.2.0 的每包容量为 8 颗，历史表只记录总颗数，不保留逐档用量。它们仍出现在总数中，并单独提示“旧版记录”，不会混算成新规格包装。旧版未记录香烟、提前放下、呼吸或现实打卡，不会自动补造这些数据。

## 用量提醒与成就

今日嚼过/点燃数量在页面直接显示，达到 **5 颗或 5 根**时显示自省提醒；这是提醒线，不是安全剂量，也没有奖励或需要完成的挑战。

成就共 9 项：

| 成就 | 条件 |
| --- | --- |
| 开始觉察 | 首次留下模拟用量记录 |
| 把下一口留下 | 首次在模拟中提前吐出或主动提前熄灭 |
| 先停一分钟 | 完整完成 1 次呼吸练习 |
| 给自己一点空间 | 累计完成 3 次呼吸练习 |
| 现实第一步 | 至少 1 天自行确认现实没有使用槟榔或香烟 |
| 给口腔一个休息 | 曾连续 3 天打卡现实没嚼槟榔 |
| 三天清新 | 曾连续 3 天打卡现实没吸烟 |
| 清新的一周 | 曾连续 7 天打卡现实两者都没使用 |
| 把健康留成习惯 | 曾连续 30 天打卡现实两者都没使用 |

成就由服务端从持久化计数与打卡重新计算，没有重复领奖接口；同一个操作重试不会多计，换设备登录同一账号会看到同样记录。

## 现实打卡

打卡是自愿的个人确认，与模拟统计完全分开。**没打开网页、模拟次数为零，不代表现实戒除成功。**

可以记录或更正北京时间今天及前六天。今天的勾选表示“截至目前没有使用”；当天稍后情况变化可撤回确认。过去日期表示自己对该日的确认。未勾选表示未确认，不自动推断使用情况。

- 同一天反复保存只更新该天，不累计天数。
- 连续天数展示到最近确认的今天或昨天；缺少日期或撤回确认会中断连续。
- 保留根据现存打卡计算出的历史最佳连续天数。
- 中断后，已达到的历史最佳里程碑保留；如果更正旧打卡使历史最佳也不成立，对应成就会重新计算并取消点亮。
- 打卡需联网成功保存；失败时页面显示“尚未保存”，不会虚报同步成功。
- 没有在线打卡之外的后台行为监测，也不收集现实使用传感数据。

## 同步与技术说明

模拟操作以事件序号和独立流水保存，MySQL 事务校验、去重。新事件使用协议 2 和专用 /api/events-v2 接口（旧后台会拒绝，不会误按 8 颗计数），旧版队列使用协议 1 和 /api/events，由冻结的 1.2 模型重放。新旧流水不能混用协议。烟的自然燃烧以整数毫秒累积，最多约每 5 秒上传一次燃烧事件，吸吐或熄灭前也会补齐，避免帧率差异导致多计。

新增表为 `chew_activity_daily`（逐档槟榔、香烟和休息计数）、`chew_checkins`（现实打卡）。原有 `chew_daily`、账号、会话和流水表保留不变。新增 `POST /api/checkin`，要求当前会话与 `accountId` 一致；`GET /api/stats` 增加活动字段和 `progress`（包装、打卡日历、连续天数、成就、今日提醒）。

离线模拟补传继续按服务器收到当天计入，不按客户端时钟回填。打卡可以明确选近 7 天的日期。模拟事件不是防作弊验证；伪造合法操作序列仍可能改变虚拟数据，所以没有竞技排行。

从 1.2.0 升级时按 [账号服务器部署指南](accounts-server.md)运行新安装脚本，输入 MySQL 管理凭据创建新增表。应用仍使用原来的有限权限服务账号。不要清空数据库或覆盖 `.private/server.json`。本次没有重建 EXE / APK，现有客户端仍是 1.1.1 离线版。

## 现实戒除省钱估算

在“记录与成就”填写以前的槟榔每袋价格、规格（10 / 15 / 20 颗）、每日颗数，以及香烟每盒价格（20 根）、每日根数；未使用项目填 0。未设置前不显示金额。

槟榔估算 = 已确认没嚼槟榔的天数 × 每袋价格 × 每日颗数 ÷ 每袋容量；香烟按已确认没吸烟的天数、每盒 20 根同样计算。分别汇总后四舍五入到分，再合计。只统计现实打卡，不把模拟用量、未登录或未打开网页当成省钱。

当前设置回算全部历史打卡；修改设置、撤回打卡会立即重算，今天尚未结束，金额只是暂估。清除花费设置不删打卡或模拟历史。设置保存到当前账号，断网会提示未保存；登录另一个账号不显示前一账号金额。
